** DONE BUG Filenames with spaces break ffprobe in mp3-duration-ms
   Filenames like "2026-07-01 21_46_39.mp3" contain a space between date and
   time. mp3-duration-ms passed them unquoted to execSync, so ffprobe received
   a split path ("Downloads/2026-07-01" and "21_46_39.mp3" as separate args).
   This caused false BROKEN status and unnecessary re-downloads on every file.

   Symptoms:
   - "Argument '21_46_39.mp3' provided as input filename, but
     '/home/.../Downloads/2026-07-01' was already specified."
   - "BROKEN ... ffprobe FAIL -> re-download" on files that are actually
     healthy. Every file was affected — all filenames have a space in them.

    Fix: replaced execSync (shell string) with execFileSync (argv array):
      (.execFileSync cp "ffprobe" #js["-v" "error" ... file-path])
    The argv array goes directly to ffprobe — the shell never sees it,
    so spaces in paths are handled correctly.
** TODO BUG read-staging-org regex fails to match TODO headlines with trailing content
   In read-staging-org (jstavel/org-staging/core.clj), the pattern #"\* TODO"
   is passed to re-matches, which requires full-string match. Headlines like
   "* TODO ingested.mp3" or "* TODO pending.mp3  :;" fail because re-matches
   does not match partial strings. re-find should be used instead.

   Impact:
   - read-staging-org returns empty set from staging.org entries
   - Hash extraction tests fail (7 failures in total)
   - scan-and-stage-downloads cannot detect already-staged files → no idempotency
   - All hash-related tests show "-" prefix on expected strings

   Fix: replace re-matches with re-find in the hash-extraction pipeline.

** TODO BUG fp/list-audio-files uses Files/walk — recursive when flat required
   Per specification §3.1 and use case 0003, Downloads scanning must be flat
   (non-recursive) — only files directly in the top-level Downloads/ directory.
   However, fp/list-audio-files uses `Files/walk` which recurses into all
   nested subdirectories.

   Impact:
   - Files in nested dirs (e.g. Downloads/foo/bar.mp3) are incorrectly picked up
   - Subdirectories meant for archiving (e.g. Downloads/old/) leak into staging
   - Violates spec: "Nested subdirectories are ignored"

   Fix options:
   - Add a flat-only `list-files` to fp component using `Files/list`
   - Or add a `:max-depth` parameter to `list-audio-files` (default 1 for Downloads)
   - Prefer: separate `list-files-flat` for clarity — Downloads is a special case
   Ref: docs/specification.md §3.1, docs/usecases/0003-staging-metadata-enrichment.md §1
